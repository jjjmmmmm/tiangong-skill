# 阶段五 · 主路径贯通与可演示

目标：从入口到结果走通立项定下的主路径（允许标明的假实现）；产出可复现的演示说明与差距清单。

## 端到端贯通

- 用意图驱动：用自然语言说清"用户完成哪条路径、应看到什么"，让模型生成可点击或可运行的样本，再迭代。
- 外部依赖未就绪时，用已约定的临时假实现顶替，并在界面或文档中标明。
- **禁止**：关键步骤只靠口头"假装成功"，演示说明里却写成已完成。
- **禁止**：页面看起来完整，就把未实现的能力写进文案——以实际操作为准。

## 演示说明（demo.md）

结构：环境前提 → 编号步骤 → 每步预期现象 → 常见失败检查。

- 试讲：另一人（或另一会话）只按文档操作，其他人不得口头补步骤——目的是找出只有作者才懂的省略。
- 够用标准：第二方能独立走通；缺步当场补进文档。
- 只有功能列表、没有逐步操作的演示说明不算完成。

## 差距清单（gaps.md）

演示中"尚未做完但后续要做"的每一项，写清：描述、优先级、计划在哪个阶段做、负责人。

- 阻塞主路径真实可用的最先做；体验类可明确标"不做"（例：管理端美化——不做）
- 每条差距改写为**四要素任务**（约束/需求/范围/输出），不得写"继续完善""优化体验"等无法验收的句子
- 选出可并行的块，准备按"计划—执行—核对"推进

## 演示通过 ≠ 可交付

演示通过只证明：演示者本机、按一条已知路径、得到预期结果。仍需证明：陌生人按文档能否复现；错误输入是否被拒绝；权限是否在服务端生效；临时假实现是否被误当真实实现。

## 迭代顺序

先贯通主路径，再按差距清单逐项增加。一次生成"完整产品"通常会在中间某处静默失败。

## 通过标准（自检）
- [ ] 他人可按演示说明复现主路径
- [ ] 假实现全部标明
- [ ] 差距清单可排期、可验收（没有形容词条目）

## 本阶段易错
- 依赖尚未就绪，又未使用已约定的临时假实现
- 演示说明只有功能列表，没有逐步操作
- 试讲时作者不断口头提示，文档漏洞未暴露
- 差距清单全是形容词，无法排期与验收
