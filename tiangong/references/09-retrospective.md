# 阶段九 · 结项复盘与大报告

目标：一份报告说清做了什么、做到哪一步、如何验证——读者仅凭正文与插图即可核查，无需口头补充。

## 完成情况对照表

立项的每条必做一行，结论三档：完成 / 部分完成（写清边界）/ 未做。

例：提交可用，真实评测机回调仍用本地替身。

## 方案与验证

- 背景与目标；方案摘要；主路径；测试或演示说明
- 用一小段写清：演示说明覆盖哪条场景、流程纪律写在哪些文件

## 分工

谁做了哪一块，能对上 Git 作者或文档、测试职责。不写"全员共同完成"。

## 复盘写法（举事实，不写感想）

- **阻塞**：两至三个真实卡住的问题——定在哪一层、改了哪次提交、哪条通检因此通过（可引用联调记录）
- **方法实践**：各举一件事实——任务是否写成四要素；是否小步推进；合并前是否审阅改动；排错是否写齐五项；清单是否写了验证方式
- **若有更多时间会改什么**

## 归档

README、演示说明、测试记录入仓库归档。不要只留下聊天记录。

## 九阶段用过的方法（总结备查）

- **下任务**：约束、需求、范围、输出
- **上下文**：项目备忘与当天计划写入仓库，不依赖超长对话
- **质量**：审阅改动后再合并；计划—执行—核对；排错写齐五项
- **交付**：演示说明可复现；README 使他人能够启动；通检与回归

## 新项目怎么复用本法式

- **开头**：先写边界与验收标准，再生成代码
- **中段**：一次做一块可验证的增量；接口或选型有变，当天改备忘
- **收尾**：按清单回归；归档 README、演示说明、测试记录

## 通过标准（自检）
- [ ] 必做逐条有结论，与完成情况对照表一致
- [ ] 主路径与验证说得清，不是目录粘贴
- [ ] 材料可独立阅读核查；无密钥、无大段无关文字充数

## 本阶段易错
- 复盘只有感想，没有对照必做的完成情况
- 主路径说不清，只有目录粘贴
- 报告里放密钥，或大段无关文字充数
