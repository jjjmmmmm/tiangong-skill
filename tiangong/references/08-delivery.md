# 阶段八 · 验证与交付准备

目标：回归、文档定稿、交付演练、清单验收，使他人能启动、自测有结论。

## 回归

修复之后，把通检、已有的单元与集成用例、演示说明再跑一遍，确认旧路径未被破坏。

- **快速通检**：改完立刻运行的一小套用例，防止主路径当场失效
- **回归**：修完缺陷或隔段时间后重跑已有用例，防止修好一处弄坏另一处
- 向模型要测试时写明：测哪条路径、输入是什么、期望输出是什么——不要只说"随便加几个测试"

## README 定稿

写安装、配置、启动、停止。使用场景怎么点，沿用演示说明；这里只写到"能启动"。

## 交付演练

- 从较干净的状态（新目录 / 新环境）按文档走通
- 预先想好：构建失败、端口占用、忘记初始化数据时如何处理
- 若有脚本，做一次回退演练

## 验收自测表（acceptance.md）

对照立项必做与验收标准逐项勾选：

- 结论三选一：通过 / 未通过 / 不适用
- **通过**须指向命令、演示步骤或通检编号
- **未通过**须指向缺陷或遗留说明
- **不适用**须写理由（例：立项写明不做管理端美化，该行标"不适用"并注明出处）
- 只打勾、没有验证方式，等于未填

## 审查清单

由人（或审阅会话）勾选并写明验证方式，不把模型生成的"全部通过"报告直接上交：

- **逻辑**：主路径与失败路径是否与书面约定一致
- **可维护**：有无大段重复生成代码、无名关键数字、目录混乱
- **依赖真实**：包能否安装、调用的接口是否存在（依赖幻觉以能装能跑为准）
- **合并纪律**：未通读的大块改动不直接合入主分支

## 安全清单（最低集，每项写清如何验证过）

- [ ] **密钥**：仓库与日志中无真实密码、令牌
- [ ] **输入**：外部输入在服务端校验
- [ ] **鉴权**：需登录的接口在服务端强制检查
- [ ] **拼接**：SQL 或系统命令不用用户字符串直接拼接

## 安全写进任务约束

向模型下任务时，在约束中写明：不得提交密钥、不得去掉服务端校验、不得引入未说明来源的安装脚本。不写进约束，模型容易为了先跑起来而把密钥写进配置或拆掉挡请求的校验；写了仍须由人审阅改动。

## 通过标准（自检）
- [ ] 他人可按 README 启动（不只是演示者本机）
- [ ] 验收自测表主要项有结论、有凭据
- [ ] 重要缺陷清零；安全清单每项有验证方式

## 本阶段易错
- 清单全部打勾，无验证方式
- README 只有技术栈列表，无启动命令
- 只演示启动成功，未考虑停止或回退
- 重要缺陷带入结项
